# 편집 객체 설계 (설계 17, 2026-11-05)

대조 때 「다음으로」 미룬 묶음의 설계다: 편집 객체·주석·양식 칸의 자르기·복사·붙여넣기, 주석 여러 쪽에 적용, 쌓는 순서, 맞춤·분배, 글 넣는 엔진을 `insert_htmlbox` 로 바꾸는 일.
조정 세션은 아래 「덩어리 표」대로 Opus 세션을 띄운다. 기준은 양식 다듬기·PPT 글 상자 가지를 합친 뒤의 main 이다.

## 1. 목표

- 편집 모드에서 고른 그림·글 덩어리를 자르고 복사해 같은 쪽·다른 쪽·다른 탭 문서에 붙인다.
- 주석 하나를 자르고 복사해 붙이고, 같은 자리로 여러 쪽에 한 번에 넣는다.
- 편집 객체의 쌓는 순서를 넷(맨 앞으로·맨 뒤로·앞으로·뒤로)으로 바꾼다.
- 편집 객체 여러 개를 골라 맞춤 여섯·쪽 가운데 셋·분배 둘을 한다(양식 칸은 라운드 16 에 이미 됨).
- 편집 글과 글 주석을 `insert_htmlbox` 로 그려 밑줄·취소선·줄 간격·문자 간격과 글 주석 글꼴 고르기를 연다.
- 위 명령은 전부 실행 취소 한 걸음이다.

## 2. 경계

- 양식 칸의 복사·붙여넣기·맞춤·분배는 지금 코드(`form_tools.py`·`annots.paste_fields`)를 그대로 쓴다. 클립보드 자리만 공용 모듈로 옮긴다.
- 쪽 썸네일의 쪽 복사·붙여넣기는 건드리지 않는다.
- 옛 열쇠(`RPDFA` 그림 감싸기, `/RPDFDeco`)는 이름과 모양을 바꾸지 않는다. 새 열쇠도 `RPDF` 머리를 쓴다.
- 분석 명세의 내용은 이 문서와 코드 주석에 옮겨 적지 않는다. 덩어리 세션은 필요한 줄만 원본 경로에서 읽는다.

## 3. 확인한 사실 (PyMuPDF 1.27.2.3, 이 설계 중 실험)

1. `insert_image`·`insert_textbox`·`insert_htmlbox` 는 부를 때마다 내용 스트림을 하나 더 붙인다. 그런데 교정(`apply_redactions`, 글 고치기·그림 지우기가 씀)을 한 번 하면 쪽 내용이 한 스트림으로 합쳐지고 자원 이름(`/fzImg0` → `/Im1`)과 Form 번호가 바뀐다. 스트림 번호·자원 이름·xref 로는 객체를 다시 찾을 수 없다.
2. 표식 구간(`/이름 <<…>> BDC … EMC`)은 교정과 `clean_contents` 뒤에도 남는다. 공백은 붙어 나오고(`/RPDFObj<</Id 2/K/I>>BDC`), `q /이름 Do Q` 는 `/이름 Do` 로 줄어 나올 수 있다. Form 사전에 넣은 사설 열쇠(글자열)도 남는다.
3. 표식 구간 둘의 자리를 스트림 안에서 바꾸면 그리는 차례가 바뀐다. 쪽의 그리는 차례는 `page.get_bboxlog()` 로 읽는다.
4. `insert_htmlbox` 는 글을 Form XObject 로 넣는다(쪽 내용은 `q /fzFrm0 Do Q` 한 줄). 글 추출(`get_text`)과 교정은 Form 안까지 들어간다. 밑줄·취소선은 선으로 그려져 글만 지우는 교정으로는 남는다.
5. CSS 는 `text-decoration`(밑줄·취소선)·`letter-spacing`·`line-height`·`text-align`·`vertical-align` 이 먹는다. `<u>`·`<s>` 태그는 안 먹는다. `@font-face` 에 윈도우 글꼴 파일(.ttf·.ttc)을 주면 그 글꼴로 그린다. 기울임 파일이 없는 글꼴은 `font-style: italic` 이 안 먹는다. 상자에 안 들어가면 `(-1, 배율)` 을 돌려주고 `Story.fit_height` 로 필요한 높이를 잰다. `rotate`(90 단위)·`opacity` 를 받는다.
6. 리치텍스트 글 주석(`add_freetext_annot(richtext=True)`)은 설치 글꼴을 쓰지 못하고 내장 글꼴로 대신 그린다(지금 `_ds_css` 의 「Malgun Gothic」도 실제로는 내장 한글 글꼴). 외관을 우리가 지어 `/AP /N` 에 넣으면 저장하고 다시 열어도 남는다. 다만 `annot.update()` 를 부르면 MuPDF 가 자기 외관으로 다시 덮는다.
7. `insert_htmlbox` 한 번에 글꼴 파일이 통째로 실린다(맑은 고딕 보통·굵게 26MB). `doc.subset_fonts()` 는 0.05초이고 그 뒤 글 객체 하나에 0.6MB(압축 전)다. 실행 취소가 문서 사본을 통째로 쌓으므로 쓴 직후 줄여야 한다. 단, 열려 있는 문서에서 줄인 뒤 같은 자원 이름으로 `insert_font` 를 부르면 줄인 글꼴을 다시 써서 새 글자가 빈 네모로 나온다(`insert_textbox` 를 쓰는 꾸미기·스탬프·교정 글자 경로). 지금 저장 길에서는 생기지 않는다.

## 4. 설계

### 4.1 편집 객체와 표식

- **객체 줄**: 우리가 만드는 편집 객체는 쪽 내용 맨 바깥(기본 좌표계)에 놓인 XObject 그리기 한 줄이고 표식으로 감싼다.
  `/RPDFObj <</Id n /K /I>> BDC q a b c d e f cm [/RPDFA숫자 gs] /이름 Do Q EMC`
  `K` 는 `/I`(그림)·`/T`(글). `Id` 는 그 쪽 안에서만 유일한 정수(쪽의 가장 큰 Id + 1). 그림의 안쪽 모양은 지금 `transform_image` 가 쓰는 감싸기 그대로라 `_image_spot` 이 그대로 찾는다.
  읽는 정규식은 공백 없는 꼴과 `q … Q` 없이 `/이름 Do` 만 남은 꼴을 다 받는다. 객체의 정체는 `Id` 뿐이다.
- **글 객체의 서식**: 글을 담은 Form 사전에 `/RPDFText`(JSON 글자열: 글·글꼴·크기·색·굵게·기울임·밑줄·취소선·정렬·줄 간격·문자 간격·상자·회전)를 적는다. 다시 고칠 때 글자 조각에서 짐작하지 않고 이것을 읽는다.
- **원문 객체**: 표식 없는 그림과 글은 원문이다. 원문 그림은 쌓는 순서·복사에 처음 쓰일 때 「들어올린다」(원래 `Do` 를 지우고 쪽 기준 행렬을 계산해 객체 줄로 다시 놓음). 원문 글은 지금 옮기기·고치기와 같은 길(그 자리 글만 지우고 우리 글 객체로 다시 씀, 바탕 흰 칠 없이)로 들어올린다.
- **제자리 바꾸기**: 우리 객체를 고치거나 옮기거나 크기를 바꿀 때는 그 줄 자리에서 바꿔 쓴다(글은 새 Form 을 만들고 줄의 이름만 바꿈). 그래야 쌓는 순서가 유지된다.
- 객체 줄을 놓기 전에 쪽이 감싸여 있는지(`page.is_wrapped`) 보고 아니면 `wrap_contents()` 를 부른다.

### 4.2 앱 안 클립보드

- 새 `app/ui/clipboard.py` 한 벌에 **종류별 칸 셋**: `fields`(양식 칸, 지금 `form_tools.CLIP` 을 옮김)·`annots`(주석)·`objects`(편집 객체). 탭·창 사이에서 같이 쓴다.
- 칸에 담는 것은 다시 만들 수 있게 적은 자료(spec)다. 원본을 지우거나 실행 취소해도 붙일 수 있고 다른 문서에도 붙는다(객체 번호를 담지 않는다. 같은 문서일 때만 그림 xref 를 다시 써서 파일이 안 커지게 함).
  - 편집 그림: 그림 바이트(투명은 알파를 살림)·쪽 기준 행렬·불투명도.
  - 편집 글: `/RPDFText` 와 같은 서식 묶음. 원문 글은 `block_style` 로 읽은 값.
  - 주석: 지금 `export_annots` 항목 꼴에 스탬프·서명(외관 PNG)·첨부(파일 바이트·이름·아이콘)·측정 선(축척·라벨 열쇠)을 더한 것. 답글은 담지 않는다.
- **붙여넣기는 지금 모드에 맞는 칸만 본다**: 손·선택 = 주석, 편집 모드 = 편집 객체, 양식 편집 = 양식 칸. 칸이 비면 메뉴가 꺼진다.
- 자리: Ctrl+V 는 지금 쪽의 같은 자리(같은 문서 같은 쪽이면 10pt 비켜서), 오른쪽 클릭 붙여넣기는 누른 자리에 묶음의 왼쪽 위. 쪽 밖으로 나가면 쪽 안으로 당긴다. 붙인 것은 고른 상태로 둔다.
- 시스템 클립보드: 복사할 때 그림은 그림으로, 글은 글자로 같이 올리고 우리 표시(`application/x-pdfmetry-clip`, 값은 복사 번호)를 단다. 편집 모드에서 붙일 때 표시가 우리 번호와 같으면 우리 칸을, 다르면 시스템 클립보드의 그림·글자를 새 객체로 넣는다.
- 탭을 닫으면 칸에 적힌 문서 표시(`doc`)를 지워 같은 번호의 새 문서를 원본으로 잘못 알지 않게 한다.
- 단축키: Ctrl+C·X·V 가 모드에 따라 위 세 칸으로 간다. 글자를 고른 상태의 Ctrl+C(글자 복사)는 그대로다.

### 4.3 실행 취소

- `Document.batch()` 문맥 관리자를 더한다: 들어갈 때 사본 한 번, 안에서 부른 `snapshot()` 은 무시, 겹쳐 써도 된다.
- 여러 엔진 함수를 묶는 명령(붙여넣기·자르기·여러 쪽 적용·맞춤·분배·묶음 옮기기·묶음 삭제·쌓는 순서)은 `with doc.batch():` 안에서 돈다. 자르기는 복사(문서 안 바꿈) 뒤 삭제 한 걸음이다.
- 실행 취소·다시 실행 뒤에는 고른 것을 푼다(Id·xref 가 가리키는 것이 달라질 수 있음). 클립보드 칸은 그대로 둔다.

### 4.4 주석 여러 쪽에 적용

- 주석 오른쪽 클릭 「여러 쪽에 적용」 → 쪽 범위 창(공용 쪽 범위 칸 `dialogs.PageRangeEdit` 을 그대로 씀) → 고른 쪽마다 보이는 화면 기준 같은 자리에 같은 주석을 만든다. 원본 쪽은 건너뛴다. 한 걸음.
- 되는 종류: 도형·선·연필·글상자·스탬프·서명·노트. 글자 표시 주석(강조·밑줄·취소선·구불선)·교정 표시·첨부·답글은 메뉴를 끈다.
- 쪽 크기가 달라 자리가 쪽 밖이면 그 쪽은 건너뛰고 상태줄에 「N쪽에 적용, M쪽 건너뜀」.

### 4.5 쌓는 순서

- 쪽 내용을 맨 바깥에서 「덩이」로 나눈다: 객체 줄 하나가 한 덩이, 그 사이의 표식 없는 내용은 통째로 한 덩이(원문 덩이).
- 맨 앞으로 = 객체 줄을 쪽 내용 끝으로, 맨 뒤로 = 처음으로. 앞으로·뒤로 = 이웃 덩이 하나와 자리 바꿈.
- 원문 객체는 먼저 들어올린다. 원문 덩이 안에 있던 객체의 「앞으로」는 그 원문 덩이 바로 뒤, 「뒤로」는 바로 앞이다.
- 원문 덩이의 `q`·`Q` 가 맞지 않거나(글자열·인라인 그림을 건너뛰고 셈) 그림이 다른 Form 안에 그려져 있으면 바꾸지 않고 「이 객체는 순서를 바꿀 수 없습니다」.
- 들어올리면 원래 걸려 있던 자르기(clip)는 사라진다(감수).
- 주석과 양식 칸의 쌓는 순서는 만들지 않는다.

### 4.6 여러 개 고르기 · 맞춤 · 분배

- 편집 모드에서 Ctrl·Shift+클릭으로 더하고 빼기, 빈 곳 끌기로 걸친 것 고르기, Ctrl+A 로 그 쪽 전부. 뷰어에 `sel_objs`(같은 쪽 안, 고른 차례)를 두고 마지막 것이 `sel` 이다(양식 칸의 `sel_fields` 와 같은 모양).
- 묶음으로 끌어 옮기기·삭제·자르기·복사가 된다. 크기 바꾸기 손잡이와 속성 패널 값은 마지막 하나에만.
- 맞춤 여섯(둘 이상)·분배 둘(셋 이상)·쪽 가운데 셋(하나부터). 계산은 양식 칸과 같은 규칙(`tools.align_widgets`)을 네모 목록 계산 함수로 떼어 같이 쓴다. 보이는 화면(쪽 회전 반영) 기준이다.
- 화면: 오른쪽 클릭 메뉴의 「쌓는 순서」「맞춤」「분배」 펼침, 속성 패널에 「정렬」 묶음(단추), 편집 리본에 「정렬」 펼침 단추.

### 4.7 insert_htmlbox 전환

- 새 `app/engine/textbox.py`: 서식 묶음 → HTML·CSS 짓기(줄마다 `<p>`, 글자 이스케이프), 글꼴 묶음(`fonts.font_file` 로 찾은 파일을 `@font-face` 로, 쓰는 얼굴만), 쪽에 글 객체 쓰기, 글 주석 외관 짓기.
- **편집 글**: `add_text`·`edit_block`·`_insert_box` 가 `textbox` 로 쓴다. 지금 동작을 지킨다: 글 방향 = 쪽 회전 + 보기 회전, 넘치면 글 방향 아래로 늘림, 원문 고치기(`grow`)는 줄바꿈 대신 너비를 늘림(정렬 쪽 붙박음), 빈 글이면 지움. 굵게 파일이 없으면 지금처럼 획을 더해 흉내, 기울임 파일이 없으면 객체 줄의 행렬에 기울임을 넣어 상자째 기울인다.
- 새 서식: 밑줄·취소선·줄 간격·문자 간격(상자 단위). `props_content.py` 글자 칸과 `inline_text.py` 떠 있는 막대·제자리 편집 화면에 같은 값을 보인다(화면 글 상자의 줄바꿈이 쪽 결과와 어긋나지 않게 Qt 글자 간격·줄 높이도 맞춤).
- 쓴 직후 `subset_fonts()` 로 줄인다. 그 전에 3절 7의 빈 네모 문제를 막는다(줄인 글꼴 이름을 문서 전체에서 피하도록 `korean_font_name` 과 `insert_font` 를 부르는 곳의 이름 고르기를 고침). 못 막으면 줄이기를 저장 때로 미루고 `@font-face` 얼굴 수만 줄인다.
- **글 주석**: 외관을 `textbox` 로 지어 `/AP /N` 에 넣는다(테두리·바탕·말풍선 지시선 포함). `/DA`·`/DS`·`/RC`·`/Contents` 는 지금처럼 써서 다른 편집기가 다시 그릴 수 있게 둔다. `/DS` 의 `font-family` 가 그 주석의 글꼴이다. 글 주석을 건드리는 모든 길(`_add_free_text`·`_ft_redraw`·`update`·`edit_free_text`·옮기기)의 끝에서 외관을 다시 입힌다.
- 환경 설정 「주석 텍스트 박스 글꼴」에 글꼴 칸을 더한다(`comment_font["font"]`, 글꼴 이름 글자열, 없으면 맑은 고딕). 제자리 편집 화면도 그 글꼴로 보인다.

### 4.8 옛 문서 호환

- 옛 버전이 `insert_textbox` 로 쓴 글은 원문 글로 다룬다(고치거나 옮기면 그때 글 객체가 됨). 일괄 변환은 없다.
- 옛 글 주석(보통·리치 둘 다)은 손대기 전까지 외관을 그대로 둔다. 고치면 새 방식으로 다시 그린다. 글꼴은 `/DS` 의 이름이 설치 글꼴이면 그것, 아니면 맑은 고딕이다(지금까지 내장 글꼴로 보이던 글의 줄바꿈이 조금 달라질 수 있음).
- 옛 `RPDFA` 감싸기 그림은 표식이 없어도 지금처럼 고쳐지고, 쌓는 순서·복사에 처음 쓰일 때 표식이 붙는다.
- `annots.json` 내보내기·XFDF 꼴은 바꾸지 않는다(글꼴 이름 칸 하나만 더함, 없으면 맑은 고딕).
- 글 객체는 표준 Form XObject 라 다른 보기 프로그램에서 그대로 보이고 글 찾기·복사·변환도 된다.

## 5. 단계와 덩어리 표

1단계는 가·나 동시, 2단계는 1단계를 합친 main 에서 다 하나. 같은 단계 안에서는 파일이 겹치지 않는다.

| 가. 객체·주석 복사 엔진 | 1 | 새 `app/engine/objects.py`·`app/engine/annot_clip.py`, 새 시험 `test_objects.py`·`test_annot_clip.py`. 있던 파일은 안 고침 | 표식 줄 읽기·쓰기가 교정 뒤에도 Id 로 찾아짐 · 원문 그림 들어올리기 뒤 화면이 같음 · 순서 넷이 `get_bboxlog` 차례로 확인됨 · 그림 spec 을 다른 문서에 붙이면 같은 모양 · 맞춤·분배 계산 함수 · 주석 spec 으로 종류마다 붙여 넣은 것이 원본과 같은 값(스탬프·첨부·측정 선 포함) · 여러 쪽 적용 한 걸음 | Opus |

덩어리 사이 약속(1단계 → 2단계가 쓰는 이름):

- `objects`: `list_objects(doc, page)`(그리는 차례, `{id, kind, rect, xref, ours}`) · `find(doc, page, rect, kind)` · `lift(doc, page, ref)` · `order(doc, page, ref, how)`(`front`·`back`·`forward`·`backward`) · `spec(doc, page, ref)` · `paste(doc, page, specs, dx, dy)` · `move(doc, page, refs, dx, dy)` · `delete(doc, page, refs)` · `arrange(rects, how, page_rect)`(순수 계산, 새 네모 목록).
- `annot_clip`: `annot_spec(doc, page, xref)` · `paste_annots(doc, page, specs, dx, dy)` · `apply_to_pages(doc, page, xref, pages)`(넣은 수·건너뛴 수) · `can_apply(kind)`.
- `annots`(나): `add_text`·`edit_block` 은 지금 인자를 그대로 받고 끝에 `style: dict | None` 을 더하며 만든 글 객체의 Id 를 돌려준다. `free_text` 에 `family` 를 더한다. `block_style` 은 글 객체면 `/RPDFText` 를 돌려준다.
- 표식 형식(4.1)은 가와 나가 각자 구현한다. 2단계에서 다가 가의 읽기 함수 하나로 모은다.
- 설정 열쇠: `comment_font["font"]`(글꼴 이름), `addtext_style` 에 `underline`·`strike`(참·거짓)·`line_height`(배수, 기본 0 = 글꼴 기본)·`letter_spacing`(pt).

합칠 때 볼 이음새: 나가 쓴 글 객체를 가의 `list_objects`·`order` 가 읽는지(1단계 합친 직후 시험 하나), 양식 다듬기 가지와 `annots.py`·`viewer.py` 가 겹치지 않는지.

## 6. 안 하는 것

- 글자 일부만 서식(부분 굵게·위 첨자·아래 첨자)과 단락 간격. 서식은 상자 단위다.
- 주석 여러 개 고르기와 주석끼리 맞춤·분배. 복사·여러 쪽 적용은 하나씩이다.
- 주석·양식 칸의 쌓는 순서.
- 다른 Form 안에 그려진 그림과 선·도형(벡터)의 편집 객체화.
- 옛 글·옛 글 주석의 일괄 변환.
- 주석마다 속성 패널에서 글꼴 바꾸기(환경 설정의 기본 글꼴만).
- 편집 객체 「개체 잘라내기」(그림 일부 잘라 보이기)와 「이미지 편집」.

## 7. 열린 질문 (권장안, 답이 없으면 권장안대로)

1. **원문 글의 쌓는 순서·복사**: 우리 글 객체로 다시 써야 해서 글꼴을 못 찾으면 맑은 고딕으로 바뀐다. 권장: **허용한다**(지금 옮기기·고치기와 같은 규칙이고, 바뀌면 상태줄에 「글꼴을 맑은 고딕으로 바꿈」 한 줄).
2. **붙여넣기 범위**: 권장: **모드별 칸 셋**(손·선택 = 주석, 편집 = 편집 객체, 양식 편집 = 양식 칸). 한 칸에 마지막 복사만 두는 방식은 모드를 오갈 때 붙일 것이 사라져 쓰기 불편하다.
3. **다른 프로그램에서 복사한 그림·글 붙이기**(편집 모드): 권장: **넣는다**(그림은 쪽에 맞게 줄여 지금 쪽 가운데, 글은 기본 서식 글 객체).
4. **글 주석 글꼴 고르는 곳**: 권장: **환경 설정 한 곳만 먼저**(새 글 주석의 글꼴). 주석마다 바꾸기는 다음으로 미룬다.
5. **편집 글 새 서식 범위**: 권장: **밑줄·취소선·줄 간격·문자 간격까지**. 첨자와 부분 서식은 제자리 편집기가 글자 일부 서식을 다뤄야 해서 따로 큰 일이다.
6. **여러 쪽에 적용 대상**: 권장: **도형·선·연필·글상자·스탬프·서명·노트만**. 교정 표시를 여러 쪽에 거는 일은 교정 패널 쪽 기능으로 따로 본다.

## 8. 함정

- 객체는 표식 Id 로만 찾는다. 교정 한 번에 스트림·자원 이름·Form 번호가 다 바뀐다(3절 1).
- 밑줄·취소선 선은 글 지우는 교정으로 안 지워진다. 우리 글 객체는 교정하지 말고 줄을 통째로 들어낸다.
- 글 주석은 `annot.update()` 뒤마다 외관을 다시 입혀야 한다. 한 곳이라도 빠지면 내장 글꼴로 돌아간다.
- 열린 문서에서 `subset_fonts()` 뒤 같은 이름 `insert_font` 는 빈 네모를 만든다(3절 7).
- 쪽 객체는 `new_page`·`reload_page` 뒤에 다시 잡는다(옛 객체로 그리면 죽음).
- 클립보드에 `setMimeData` 하는 시험은 끝에 `QApplication.clipboard().clear()`(`이어서.md` 함정).
- 같은 주석·객체를 두 덩어리가 다른 쪽에서 다루면 이음새가 빈다(`이어서.md` 라운드 9). 5절 「합칠 때 볼 이음새」 를 시험으로 확인한다.
