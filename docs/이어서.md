# PDF메트리 이어서 (갱신 2026-11-02, 라운드 6 끝 0.2.9, 다음 라운드 7)

목표 한 줄: 알PDF 의 쓰는 기능을 디테일까지 따라가는 윈도우 PDF 편집기(파이썬·PySide6·PyMuPDF).
지금 자리: 설치본 0.2.9(GitHub 공개 저장소 `kyijgnes/rpdf` 릴리스). 시험 366개 통과·3개 건너뜀.
라운드 1(11-01)에서 구성 탭 창을 명세대로: 공용 범위 칸·엄격 파서·추출 창(`dlg_extract.py`), 회전·삭제·삽입·바꾸기(`dlg_organize.py`), 분할·레이블(`dlg_split.py`).
라운드 2(11-01): 구성 리본 범위 콤보·썸네일 확대 단계·범위 칸 레이블 찾기, 자르기·페이지 크기·페이지 박스 창(`dlg_pagebox.py`), 분할선 창(`dlg_splitpage.py`), 옛 창 셋 삭제. 단축키는 명세와 대조해 이미 같음.
라운드 3(11-01): 옛 창 셋 더 삭제(`CropDialog` 는 화면에서 그려 자르기가 써서 남김), PDF에서 삽입 때 레이어 옮기기. 꾸미기 설계 `참고\설계\꾸미기.md`·편집 탭 대조 `참고\설계\대조_편집탭.md`(둘 다 git 밖) 작성.
라운드 4(11-01): 꾸미기 공용 틀(`engine/deco*.py`·`ui/dlg_deco*.py`, 왼쪽 설정·오른쪽 미리보기, 쪽 번호는 더보기로, 글꼴 칸 윈도우 글꼴 전부), 링크 창(`dlg_link.py`)과 링크 고르기·옮기기·고치기, 제자리 텍스트 추가(`inline_text.py`).
라운드 5(11-01): 꾸미기 워터마크·배경(`deco_mark`)·머리글·페이지 번호·베이츠(`deco_text`, 베이츠는 범위 밖 쪽도 셈)·템플릿(`deco_store.py`·`dlg_deco_template.py`) 명세대로, 편집 분할 단추·대상 메뉴(`viewer.edit_target`)·이미지 클릭 넣기·끌어 놓기, 옛 `LinkDialog` 삭제. 편집 탭은 속성 패널만 남음.
라운드 6(11-02): 문서 탭을 다른 창으로 옮기기(`ui/tab_detach.py`, 알PDF 엔 없는 편의). 크롬처럼 끌어내면 새 창이 따라오고 다른 창 탭 줄에 닿으면 붙음, 탭 메뉴 「새 창으로 분리」, 같은 `DocTab` 을 옮겨 고친 내용·실행 취소 유지. 실제 마우스 확인은 사용자 몫으로 남김.

## 확정 결정 (되묻지 않는다)
- 10-20 알PDF 코드·자원은 옮기지 않는다. 분석 명세를 보고 직접 짠다(`설계.md` 0절).
- 10-21 분석 자료는 공개 저장소에 두지 않는다. 저장소 밖 `참고\알PDF분석\`(git 무시)에만, 명세 내용을 커밋 메시지·주석·문서에 옮겨 적지 않는다.
- 10-21 개인 무료 비영리 배포, AGPL-3.0. 이스트소프트와 무관 문구 유지.
- 10-29 이름 PDF메트리(영문 PDFmetry). 저장소 주소·서명 머리·`/RPDFDeco` 같은 옛 열쇠는 바꾸지 않는다.
- 11-01 꾸미기: 글꼴 칸은 윈도우 글꼴 전부(한글 없으면 맑은 고딕으로 대신), 베이츠는 알PDF 대로(기본은 범위 밖 쪽도 셈, 「번호만 증가」면 넣은 쪽끼리), 「쪽 번호」 단추는 「더보기」 안 「페이지 번호」로 옮김.
- 11-01 편집 탭: 텍스트 모드(선·단락)와 처음 쓸 때 안내 풍선은 만들지 않음. 글자 서식은 굵게·기울임·크기·색·정렬까지(insert_htmlbox 전환은 나중에 따로).
- 11-01 쪽 다루는 대화상자는 알PDF 명세의 칸·기본값·문구·동작을 따른다. RPDF 에만 있는 편의는 알PDF 와 부딪치지 않을 때만 남긴다.

## 함정 (한 번 당한 것)
- 10-21 공개 전환 때 git 기록을 새로 써서 그 전 가지는 main 과 공통 조상이 없다. `git branch --no-merged` 에 다 뜨므로 끝 커밋 제목이 main 에 있는지로 판단(11-01 정리 때 10개 지움).
- 분석 자료 `참고\알PDF분석\` 는 git 밖이라 워크트리에 없다. 브리프에 전체 경로 `C:\Users\kyijgnes\Desktop\코딩\14. 도구\PDF 앱\참고\알PDF분석\` 를 적고 읽기만. 명세의 줄 번호(window.py:855 등)는 10-20 기준이라 지금 코드와 어긋난다(함수 이름으로 찾는다).
- **조정 세션은 사이드바 맨 위에 둔다**(11-01 사용자). 새 조정은 사용자가 맨 위 세션에서 「PDF메트리 이어서」로 열고, 그 세션이 스스로 「PDF메트리 조정 N」이 된다. 다른 세션 밑에 조정 세션을 띄우지 않는다(이어서 SKILL.md).
- 이 조정 세션이 다른 세션에서 시작되면 하위 세션은 카드(own_initiative)로만 띄워진다. `cwd` 를 주면 거부되니 빼고, 브리프 첫 걸음에 `git worktree add -b claude/<이름> .claude/worktrees/<이름> main` 을 적는다(패드메트리에서 당함).
- `app/ui/dialogs.py`·`window.py` 의 `pages_action` 은 덩어리마다 손대기 쉬운 큰 파일이다. 새 대화상자는 덩어리별 새 파일에 두고 `window.py` 는 분기 몇 줄만 고치게 해서 충돌을 줄인다.
- 클로드 세션 안에서 HKCU 레지스트리는 MSIX 사본이 보인다. 설치 결과는 `explorer.exe <bat>` 로 띄운 cmd 에서 본다(`설계.md` 1절).
- 시험이 실제 `%APPDATA%\PDFmetry\settings.json` 의 최근 파일 목록을 건드린 일이 있다(라운드 1 가, 옛 항목 하나가 밀려 사라짐). 시험·화면 점검은 `APPDATA` 를 임시 폴더로 돌린다. 화면 점검은 `python -m app.tests.smoke_ui`(파일로 부르면 `app` 을 못 찾음).
- 덩어리가 저마다 `window.py` 머리에 import 한 줄씩 더해 합칠 때 그 줄만 겹쳤다(라운드 1). 겹치면 둘 다 남기면 된다.
- 화면 점검이 확인 창(삭제 확인 등)에서 소리 없이 멈춘 적이 있다(라운드 1). 지금은 기본 단추로 닫지만, 끝에 `smoke ok` 가 찍혔는지 꼭 본다.
- 앱이 보관한 하위 세션의 워크트리가 detached 로 남은 일이 있다(라운드 2). 보관 뒤 `git worktree list` 로 보고 깨끗하면 `git worktree remove`.
- 같은 라운드 덩어리가 공용 틀(`deco.py`)을 고쳐야 할 때가 있었다(라운드 5 베이츠). 그 라운드에 그 파일을 맡은 덩어리가 없는지 보고 허락하고, 보드에 적는다.
- 원격이 공개 GitHub 이다. 합치기 전에 사용자에게 가지 목록을 한 번 보여 준다(코딩\CLAUDE.md 코디네이터 5).
