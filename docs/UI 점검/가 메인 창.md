# UI 점검 가: 메인 창 (라운드 22)

0.2.25 기준. 스킬 `design:design-critique` 틀(첫인상·쓰기 쉬움·시각 위계·일관성·접근성)로 메인 창만 보았다.
코드는 고치지 않았다. 고칠 것은 라운드 23 덩어리로 나눈다(맨 아래 제안).

## 상위 5개

1. **편집 객체 속성 패널이 오른쪽에서 잘린다**(상). 글자 덩어리·그림을 고르면 「기울임」「취소선」「한가운데」「맨 뒤로」 단추가 반쯤 잘려 안 보인다. 패널 폭이 `setFixedWidth(260)` 으로 묶여 있다.
2. **다크 스킨에서 편집 글 서식 단추 글자가 안 보인다**(상). 굵게·기울임·밑줄·취소선·정렬(왼쪽·가운데·오른쪽) 단추가 밝은 회색 바탕에 흰 글자로 그려진다. 일반 `QToolButton` 규칙이 테마에 없다.
3. **보기 탭 「눈금자 & 격자」가 「눈금자 _격자」로 보인다**(상). `&` 가 단축키 표시로 먹혔다. 이름은 알PDF 따름이고 깨진 표시만 우리 것.
4. **주석 탭 리본이 기본 창 폭(1456)에서도 넘친다**(중). 오른쪽 열두 개가 이름 없는 아이콘만 남고, 다른 탭은 가운데 정렬인데 이 탭만 왼쪽에 붙는다. 1024 폭에서는 「강조」「영역 강조」 둘만 이름이 남는다.
5. **리본의 꺼진 단추와 켜진 단추가 거의 같아 보인다**(중). 문서 없는 시작 화면에서 리본 단추가 전부 꺼져 있지만 글자색 차이가 작아(다크는 더 작음) 누를 수 있는 것처럼 보인다.

## 첫인상

빨강 강조색 하나로 고른 탭·켜진 도구·왼쪽 막대 표시를 묶어 어디에 있는지는 바로 읽힌다. 리본 한 줄·왼쪽 아이콘 막대·오른쪽 속성 막대 배치가 알PDF 와 같아 익숙하다.
가장 먼저 눈이 가는 것은 문서 탭의 **꽉 찬 색 닫기 네모**인데, 이것은 주인공이 아니다. 문서와 리본이 먼저 보여야 한다.

## 잘 된 것

- 강조색 하나(빨강)를 고른 탭 밑줄·켜진 도구·왼쪽 막대 표시에 일관되게 써서 지금 상태가 바로 보인다.
- 패널 머리(제목 · 아이콘 줄 · 닫기 ‹) 구조가 일곱 패널 모두 같다.
- 레이어 패널의 빈 상태 한 줄은 좋은 본보기다. 다른 빈 패널도 이렇게 맞추면 된다(#13·#14).
- 다크 스킨은 #2·#9·#20 을 빼면 바탕·글자·구분선이 고르게 바뀐다.
- 긴 탭 이름은 가운데를 줄여(「두 번째 문서 이… 긴 파일.pdf」) 앞뒤가 다 보인다.

## 라운드 23 덩어리 제안 (파일 안 겹침)

| 덩어리 | 맡는 발견 | 파일 |
|---|---|---|
| 속성 패널 | #1 #2 #6 #7 #12 | `props.py` · `props_content.py` · `props_arrange.py` · `theme.py` 중 `_toggle` 규칙 한 덩이 |

`theme.py` 는 「속성 패널」과 「화면 틀 다듬기」가 같이 쓴다. 겹치지 않게 하려면 #2 의 테마 규칙도 「화면 틀 다듬기」에 넘기거나 두 덩어리를 차례로 돌린다. 덩어리 다(접근성)가 대비 때문에 `theme.py` 를 고칠 수 있으니 조정 세션이 한 덩어리로 모으는 편이 안전하다.
