# 라운드 22 다. 접근성 점검

기준: WCAG 2.1 AA (스킬 `design:accessibility-review` 틀) · 대상: 0.2.25 (`1d11af1`) · 점검일: 2026-11-09
코드는 고치지 않았다. 고칠 후보마다 고칠 파일을 적었다. 라운드 23 덩어리 제안은 맨 아래.

## 상위 5개

| 순위 | 항목 | 심각도 | 고칠 파일 |
|---|---|---|---|
| 1 | **키보드 초점이 안 보인다.** 리본·빠른 실행·세로 막대·상태줄 단추(QToolButton 전부), 체크칸, 라디오, 문서 탭, 슬라이더, 일반 단추(인쇄·암호·OCR 창)가 초점을 받아도 모양이 그대로다(초점 전후 화면 비교로 확인). Tab 으로 51곳을 돌지만 지금 어디인지 볼 수 없다 | 상 | `app/ui/theme.py` |

## 잰 방법

- **대비**: `theme.py` 의 `LIGHT`·`DARK`·`ACCENT` 값으로 WCAG 상대 휘도 공식 계산. 글자 4.5:1, 큰 글자·아이콘·칸 경계 3:1. 기본 글꼴이 9.5pt(굵게 해도 14pt 미만)라 「큰 글자」 완화는 받지 못한다. 비활성 항목은 WCAG 면제라 숫자만 적고 미달로 세지 않았다.
- **키보드·화면 읽기**: offscreen Qt(`QT_QPA_PLATFORM=offscreen`, `QT_QPA_FONTDIR=C:\Windows\Fonts`, `APPDATA` 임시 폴더)로 메인 창과 대화상자 8개(환경 설정·인쇄·속성·암호·OCR·결합·워터마크·고급 검색)를 띄워 `focusNextPrevChild` 로 Tab 차례를 기록, 초점 전후 `grab()` 비교로 초점 표시 여부, `QAccessible.queryAccessibleInterface(...).text(Name)` 으로 화면 읽기 이름을 읽었다. 실제 NVDA·내레이터로는 듣지 않았다.
- **배율**: `QT_SCALE_FACTOR` 1.0·1.5·2.0, 메인 창은 1920×1040 실제 화소에 맞춘 논리 크기(1.5배 1280×693, 2.0배 960×520). 글자 칸의 `sizeHint` 폭과 실제 폭 비교 + 그림으로 확인. 리본 탭·인쇄 모드 탭은 `sizeHint` 상 좁게 나오지만 그림에서 안 잘려 빼냈다.
- 스크린샷: git 밖 `참고\UI점검\다 접근성\` (`main_x2.png`, `ocr_x1.5.png`, `watermark_x2.png` 등 54장).

## 가정

- 화면 크기는 1920×1080 + 작업 표시줄 40px 로 잡았다. 1366×768 노트북 150% 는 논리 911×485 라 2.0배 결과와 거의 같다.
- 화면 읽기 이름은 Qt 접근성 인터페이스 값으로 판단했다. 윈도우 UIA 가 다른 이름을 덧붙이는지는 내레이터로 들어 봐야 안다.
- 초점 표시 판단은 offscreen 그림 비교다. 실제 윈도우 스타일에서 초점 점선이 그려질 수도 있으나 QSS 가 테두리를 덮으면 Qt 는 대개 그리지 않는다.
